2. 数学直觉

只学四样东西：向量、梯度、概率、交叉熵。其余都可以现查。

1. 向量和矩阵：一批数字一起动

一个词用 4096 个数字表示，叫向量。一层网络做的事，就是把这个向量乘一个矩阵、再加个偏置。

类比：调音台上的推子。矩阵就是"每个推子对每个输出的影响权重"，一次把所有输入混成新的输出。

关键点：

  • 矩阵乘法的本质是批量做加权求和
  • 维度变化 = 信息被压缩或展开（比如 4096 维压到 32000 维的词表打分）

2. 梯度：往哪个方向调，损失降得最快

损失函数告诉你"现在错得多离谱"，梯度告诉你"每个参数往哪边挪一点能让损失变小"。

类比：蒙着眼下山。你摸脚下哪边更斜（梯度），就往那边迈一小步（学习率）。步子太大容易滚下山崖（发散），太小走到天黑（收敛慢）。

  • 学习率：步长。最常调、最容易调坏的超参
  • 局部最优：山谷里的小坑，不是最低点，但通常够用
  • 随机梯度下降（SGD）：每次只用一小批数据估梯度，快且带噪声，噪声反而有助于跳出小坑

3. 概率：模型输出的是分布，不是答案

模型最后一步是 softmax：把一堆任意实数压成"加起来等于 1 的概率"。

p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}

  • 分数高的被放大，低的被压扁
  • 温度参数就是在 softmax 前把 $z$ 除以 $T$：$T$ 大 → 分布平 → 更随机

4. 交叉熵：衡量"预测的分布"和"真实答案"差多远

如果真实下一个词是"猫"，模型给它 0.9 的概率，交叉熵就小；给 0.01，交叉熵就大。

H = -\sum_i y_i \log p_i

因为真实标签是 one-hot，实际只算一项：$-\log p_{\text{正确词}}$。

  • 交叉熵 = 训练时的损失函数
  • 困惑度（perplexity）= $e^{H}$，可以理解为"模型在多少个词里犹豫"。困惑度 10 ≈ 平均在 10 个候选里猜

一句话总结

训练的数学本质：用梯度把交叉熵压下去。所有花哨架构，都是为了让这个压的过程更有效。

  • 2. 交叉熵损失为 0 意味着什么？现实中可能吗？
  • 3. softmax 里为什么要取指数，不直接归一化？

3. 神经网络与训练

1. 一个神经元在干什么

三件事：加权求和 → 加偏置 → 过非线性函数。

y = f(w_1x_1 + w_2x_2 + \dots + b)

f 是激活函数（ReLU、GELU）。没有它，一百层叠起来也等价于一层线性变换——这就是"深度"失效的原因。

类比：每个神经元是一个"带阈值的投票员"。权重是他对每个议题的在意程度，偏置是他的立场底线，激活函数决定"票数过线才举手"。

2. 从一层到多层：表征在逐层抽象

  • 浅层学到边缘、字符、局部搭配
  • 中层学到词组、句法结构
  • 深层学到语义、意图

这是涌现的物理基础：不是谁设计了"语义层"，是优化逼出来的。

3. 参数量是怎么来的

一个 4096 × 4096 的矩阵就有 1677 万个参数。一个 7B 模型，就是七十几层这样的矩阵堆起来。

参数量 ≈ 模型"记忆容量"的上限，但不等于能力——数据质量和训练方法同样关键。

4. 反向传播：把"错多少"按责任分摊回去

前向：输入 → 一层层算 → 输出 → 和答案比 → 得到损失。

反向：从损失出发，用链式法则一层层往回算"每个参数对这个错负多少责任"，然后按责任大小调整。

类比：工厂出了次品，从成品往回追责，每道工序领到自己那份责任，各自改进。追责的依据是"你这一环变动一点，最终误差变多少"——这就是偏导。

5. 训练的基本循环

取一批数据 → 前向算损失 → 反向算梯度 → 更新参数 → 重复
名词 含义 常见坑
batch size 一次看多少条 太小噪声大，太大显存爆
epoch 把数据过几遍 大模型通常只过不到一遍
优化器 怎么用梯度更新 从 SGD 到 Adam，Adam 自适应步长更好用
正则化 防死记硬背 dropout、权重衰减、早停

6. 过拟合：背答案 vs 会做题

  • 欠拟合：训练集都做不对 → 模型太小或训不够
  • 过拟合：训练集全对，新题全错 → 死记硬背
  • 判断方法：看验证集表现，别只看训练损失

大模型时代这个词有点失效：模型大到一定程度，过拟合反而减少（双下降现象），但数据重复依然会导致记忆和泄露。

一句话总结

神经网络 = 一堆可调的加权求和 + 一个把误差分摊回去的机制。深度学习的一切复杂性，都长在这两句话上。

自测

  • 1. 去掉所有激活函数，深层网络会退化成什么？
  • 2. 反向传播为什么要用链式法则，不能每层单独算吗？
  • 3. 训练损失一直降、验证损失开始升，说明什么？

4. Transformer

这是整个现代 AI 的地基。其余都可以跳过，这一篇不行。

1. 文字怎么变成数字

"我今天很累" → [token id: 8231, 442, 91, 3377] → 每个 id 查表得到一个向量
  • 分词器（tokenizer）：按子词切，常见词一个 token，生僻词拆几块。中文一个字大约 1–2 个 token
  • 词嵌入（embedding）：一张巨大的查找表，把 id 映射成 4096 维向量。这张表也在训练中一起调

2. 注意力的核心：让每个词去"查资料"

最关键的类比：一次会议。

  • 你（当前词）有个问题（Query）
  • 每个与会者有个名牌（Key）和掌握的内容（Value）
  • 你拿问题和每张名牌比对，谁匹配度高，就多听谁的内容
  • 最后你带着"加权汇总后的信息"回去

数学上就是：

\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right)V

  • $QK^T$：问和答的匹配分数
  • $\sqrt{d}$：防止维度高时分数过大、softmax 饱和
  • softmax：归一化成"听谁的权重"
  • 乘 $V$：按权重把内容取回来

为什么要这三套权重：同一个词，作为"提问者"和"被查询者"的角色不同，所以用三个不同的矩阵从同一个向量投影出 Q、K、V。

3. 多头：同时开几场小会

把 4096 维切成 32 份，每份 128 维，各自做一次注意力，再拼回来。

好处：有的头盯语法（主谓关系），有的头盯指代（"他"指谁），有的头盯位置邻近。分工不是人为规定的，是训练出来的。

4. 位置编码：注意力本身没有顺序感

注意力是"全体两两比对"，天生不知道谁在前谁在后。所以要把位置信息注入进去：

  • 早期：正弦函数编码
  • 现在主流：RoPE（旋转位置编码），把位置写成向量的旋转角度，天然支持外推

5. 一个 Transformer 块的完整结构

输入 x
 ├─→ LayerNorm → 多头注意力 → 残差相加
 └─→ LayerNorm → 前馈网络(FFN) → 残差相加
  • 残差连接：让梯度能走捷径回传，深网络才训得动
  • LayerNorm：稳定每层输入分布
  • FFN：两层全连接 + 激活，参数量通常占整个模型的三分之二，负责"知识存储"

6. 因果掩码：为什么它只能往前看

GPT 类模型训练目标是"预测下一个词"，所以第 5 个位置不能偷看第 6 个词。做法是把上三角的注意力分数设成 $-\infty$，softmax 后权重归零。

这就是 decoder-only 架构——今天几乎所有大模型都是这个。

7. 代价：$O(n^2)$

序列长度翻倍，注意力计算量翻四倍。这就是长上下文贵的根本原因，也是各种稀疏注意力、线性注意力想解决的问题。

（注意：KV cache 让推理时的计算量线性增长，但显存占用仍随长度线性上涨，见<a href="#ch6">05-推理与部署</a>。）

一句话总结

Transformer = 用"查询—匹配—取值"的机制，让每个词按需从全句取信息，再用残差和归一化把它堆深。

自测

  • 2. 为什么除以 $\sqrt{d}$？不除会怎样？
  • 3. 因果掩码加在哪一步？如果去掉，训练目标会变成什么？
  • 4. FFN 里存的是什么？

5. 大模型训练三阶段

一个"能聊天的模型"要过三道工序。搞清楚这三步，很多现象自然就解释了。

阶段一：预训练（Pre-training）

任务极其简单：给前文，预测下一个 token。整个互联网的文本都拿来做这道题。

  • 损失函数：交叉熵
  • 数据量：几万亿 token
  • 算力：几千张 GPU 跑几个月
  • 产出：一个基座模型（base model），它只会"接话"，不会"听话"

关键规律——缩放定律（Scaling Law）：模型参数、数据量、算力三者按比例增长时，损失可预测地下降。这解释了为什么大家拼命堆规模。

Chinchilla 修正：给定算力预算，参数量和训练 token 数应大致同比例增长（约 20 token/参数）。早期模型普遍"参数太大、数据太少"。

阶段二：监督微调（SFT）

基座模型看到"请帮我写一封邮件"时，可能续写出十几封邮件——因为它在模仿互联网文本，不是在回答问题。

SFT 用人工写好的问答对教它"看到指令要回答"：

用户：把这句话翻译成英文：今天天气不错
助手：The weather is nice today.
  • 数据量小得多：几万到几百万条
  • 教会的是格式和角色，不是新知识
  • 这一步之后，模型才"可用"

阶段三：对齐（RLHF / DPO）

同一个问题，模型能给出好几种回答。哪种更好？这需要人类偏好。

RLHF：让人给回答排序 → 训一个奖励模型 → 用强化学习让模型追求高奖励。

DPO：跳过奖励模型，直接用"好回答 vs 差回答"的成对数据优化，更简单稳定，现在更流行。

对齐改变的是倾向，不是能力：更少有害输出、更愿意承认不知道、更符合指令风格。

幻觉是从哪来的

本质：模型优化的是"像不像人话"，不是"对不对"。

  • 1. 预训练目标只奖励"下一个词概率高"，不奖励"事实正确"
  • 2. 训练数据里错误信息、过时信息都会被学进去
  • 3. 采样带随机性，模型会在不确定时"顺滑地编"

所以幻觉不是 bug，是目标的必然副作用。RAG、工具调用、要求引用来源，都是在外部补上"事实校验"这一环（见<a href="#ch7">06-应用层-RAG与Agent</a>）。

三个阶段的对比

预训练 SFT 对齐
数据 万亿 token 网页 万级问答对 万级偏好对
目标 预测下一个词 模仿示范回答 符合人类偏好
得到 会接话 会听话 会分寸
成本 极高 中 中

一句话总结

预训练给它"世界的知识"，SFT 给它"回答的格式"，对齐给它"做人的分寸"。三者叠加，才有你看到的那个助手。

6. 推理与部署

训练完的模型是一堆数字文件。要让它开口说话，中间还有一整套工程。

1. 生成是"一个字一个字挤出来"的

模型每次只做一件事：给已有序列，算出下一个 token 的概率分布。然后选一个词接上去，再算下一个。

这叫自回归生成。所以输出 500 字，模型内部其实跑了 500 次前向。

2. 采样策略：怎么从概率里挑词

策略 做法 效果
贪心 每次取概率最高的 稳定但死板、易重复
温度 T 概率除以 T 再归一化 T→0 接近贪心；T>1 更发散
Top-k 只在概率前 k 个里选 砍掉长尾胡话
Top-p（核采样） 累积概率到 p 就截断 自适应候选数量，最常用

temperature 改的不是"聪明程度"，是"愿不愿意冒险"。写代码要 T=0，写诗可以 T=1.2。

3. KV Cache：为什么第二次比第一次快

生成第 N 个词时，前面 N-1 个词的 K、V 其实没变。把它们缓存下来，就不用重算。

  • 没缓存：每生成一个词，重算整段 → 平方级
  • 有缓存：只算新词 → 线性级

代价是显存：缓存大小 ≈ 层数 × 2 × 头数 × 头维度 × 序列长度 × 精度字节数。

4. 显存怎么估（重要，能手算）

推理显存 ≈ 权重 + KV cache + 激活值

  • 权重：7B 参数，FP16 约 14 GB；INT8 约 7 GB；INT4 约 3.5 GB
  • 粗略口诀：参数量(B) × 精度字节数(GB)
  • 所以 7B 想跑在 8 GB 显卡上，必须量化到 4 bit

5. 量化：用精度换显存

把 16 位浮点压成 8 位甚至 4 位整数，体积砍一半到四分之三，速度通常也变快，代价是轻微质量下降。

  • 训练后量化（PTQ）：直接压已训好的模型，简单
  • 量化感知训练（QAT）：训练时就模拟量化误差，质量更好但贵

经验：4 bit 对日常对话几乎无损，对数学和代码任务损失明显。

6. Prefill 与 Decode：两段截然不同的负载

  • Prefill：把整段输入一次性算完 → 吃算力，并行度高
  • Decode：逐个吐词 → 吃显存带宽，GPU 利用率低

这解释了为什么"输入很长"和"输出很长"的体验差异，也解释了批处理（batching）为什么能显著提升吞吐：把多个请求的 decode 拼在一起做。

7. 部署形态

形态 场景 代表
云端 API 无硬件、要弹性 各类厂商 API
本地量化 隐私、离线 llama.cpp、Ollama
自托管推理 高并发、可控成本 vLLM、SGLang、TensorRT-LLM

一句话总结

推理就是"一次次预测下一个词"，所有优化都在做两件事：少算一点（缓存/量化）、多算一点（批处理/并行）。

自测

  • 1. temperature=0 是不是完全确定？为什么现实中仍有细微差异？
  • 2. 一个 13B 模型用 INT4 跑，权重大约占多少显存？还能留多少给 KV cache？
  • 3. 为什么长上下文对显存压力是指数级的（提示：注意力 + KV cache 各贡献什么）？

7. 应用层-RAG与Agent

前面五篇在讲"模型是什么"，这篇讲"拿它做事"。绝大多数产品价值都落在这里。

1. 提示词不是玄学

模型没有记忆，它只看到你这次给的全部文本。所谓 prompt 工程，本质是在有限的上下文里把任务说清楚。

一个可用的结构：

角色 / 背景
任务（一句话）
约束（不能做什么、必须做什么）
输入数据
输出格式

最有效的三个改进：给例子（few-shot）、要求分步思考、指定输出格式。剩下都是微调。

2. RAG：把知识放到模型眼前

模型的参数里存的是"训练时截止的世界"。要它回答私有数据或最新信息，最实用的办法是把资料检索出来，塞进 prompt。

流程：

文档 → 切块(chunk) → 向量化(embedding) → 存向量库
问题 → 向量化 → 检索 top-k → 拼进 prompt → 模型作答

为什么能缓解幻觉：答案有了出处，模型从"回忆"变成"阅读理解"。再加一句"只依据给定资料回答"，效果更明显。

最容易翻车的三个点：

  • 1. 切块：切太碎丢上下文，切太大噪声多。按语义切，别按固定字数硬切
  • 2. 检索：纯向量检索对精确关键词（型号、人名）不灵，要混合关键词检索
  • 3. 重排（rerank）：先粗召回 50 条，再用小模型精排到 5 条，质量提升最明显

3. Agent：让模型自己决定下一步

普通调用是"一问一答"。Agent 是让模型在循环里自己选工具、看结果、再决定。

while 未完成:
    模型输出：我要调用哪个工具、参数是什么
    系统执行工具，把结果回填
    模型基于新结果继续推理

这就是 ReAct（Reason + Act）模式。它把模型从"生成器"变成"决策器"。

能力边界：模型只能做它见过的工具签名内的事。工具设计得越清晰（名字、参数、返回值语义明确），Agent 越可靠。

常见失败模式：

  • 死循环：反复调同一个工具 → 加步数上限
  • 幻觉工具：编造不存在的参数 → 参数校验
  • 上下文爆炸：每轮工具结果都进上下文 → 只回填摘要

4. 记忆与上下文管理

三个层次：

  • 短期：当前对话窗口，满了就丢
  • 长期：向量库 / 数据库，按需检索
  • 工作记忆：压缩后的任务状态摘要

实操里最有效的不是"更大的窗口"，而是主动摘要 + 关键信息结构化存储。

5. 怎么评估

没有评估就没有优化。三层：

层次 做法 成本
离线集 准备 50–200 条真实问题 + 标准答案 低，必做
人工抽检 每周抽 20 条看质量 中
LLM 打分 用另一个模型按维度打分 低但有偏差

关键：先把"什么算好"写成评分标准，再谈优化。否则永远在凭感觉改 prompt。

一句话总结

RAG 解决"不知道"，Agent 解决"不会做"，评估解决"不知道有没有变好"。

自测

  • 1. 什么情况下 RAG 反而不如直接微调？
  • 2. Agent 循环里，为什么工具返回结果要做摘要而不是全塞回去？
  • 3. 你的 RAG 答错了，怎么判断是检索错还是生成错？

8. 8周路线图

前提：没有编程基础。所以全程不写代码，靠图解、类比、手算和现成的可视化工具。
每天 30–45 分钟，8 周。目标是"讲得明白"，不是"做得出来"。

先想清楚：不写代码能学到哪一层

能学到：模型怎么想、为什么这么设计、哪里会出错、什么场景该用什么方案。

学不到：自己训练模型、自己写推理服务。

但说实话——90% 的实际判断力在前者。你能不能判断"这个需求该用 RAG 还是微调"，跟你会不会写 Python 没关系。

八周安排

第 1 周｜先建立整体地图

读 <a href="#ch1">00-索引</a> 和本篇；看 3Blue1Brown 神经网络系列第 1 集。任务：用自己的话写下"大模型在做什么"，三句话以内。

第 2 周｜梯度与损失（只求直觉）

读 <a href="#ch2">01-数学直觉</a>。跳过所有公式推导，只记住两个比喻：下山、调音台。任务：向家人解释"模型怎么越学越准"。

第 3 周｜神经网络

读 <a href="#ch3">02-神经网络与训练</a>。重点看"为什么必须有激活函数""反向传播是分摊责任"。任务：画一张图，标出数据从输入到输出的流向。

第 4 周｜注意力（核心周）

读 <a href="#ch4">03-Transformer</a> 前三节；去 <a href="https://poloclub.github.io/transformer-explainer/">Transformer Explainer</a> 亲手改输入，看注意力权重怎么变。任务：用"开会"这个比喻讲清 Q/K/V。

第 5 周｜完整 Transformer

读 <a href="#ch4">03-Transformer</a> 后半；去 <a href="https://bbycroft.net/llm">LLM 可视化</a> 拖动看一层层计算。任务：讲清"为什么模型只能往前看"。

第 6 周｜训练三阶段与幻觉

读 <a href="#ch5">04-大模型训练三阶段</a>。任务：写 300 字回答"AI 为什么会一本正经地胡说"。

第 7 周｜推理与成本

读 <a href="#ch6">05-推理与部署</a>。跳过 KV cache 的公式，只记结论：显存 ≈ 参数量 × 精度。任务：算一次"7B 模型 4bit 量化要多少显存"。

第 8 周｜应用层与复盘

读 <a href="#ch7">06-应用层-RAG与Agent</a>。任务：给你自己的工作或兴趣，设计一个"该用 RAG 还是该微调"的判断，写成一页。

里程碑检验（每两周一次）

  • 第 2 周：能用比喻讲清"训练"
  • 第 4 周：能讲清"注意力"，不用"注意力"三个字
  • 第 6 周：能说清幻觉的成因和缓解手段
  • 第 8 周：能对一个新需求给出技术选型判断

检验方式：讲给一个完全不懂的人听，他听懂了就算过。

不需要写代码的动手方式

想体验什么 用什么 要装东西吗

本地跑个模型 任意桌面 AI 客户端 要装，但只点鼠标
显存够不够 纸笔 + 计算器 不用

可选支线：以后想补编程

如果学到第 8 周觉得"我想自己动手做"，再考虑。顺序是：

  • 1. Python 基础（4–6 周）——变量、循环、函数、读写文件，够用就行
  • 2. numpy 和 pandas（2 周）——会算数组
  • 3. 调 API（1 周）——比自己训模型有用一百倍
  • 4. 到这一步再回看 <a href="#ch4">03-Transformer</a>，会发现突然看得懂了

不建议一上来就学编程再学 AI：两条线同时卡，容易放弃。先把"是什么"搞明白，编程只是"怎么做"的工具。
